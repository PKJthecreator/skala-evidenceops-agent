## 첫 시연 후 출력 보완

- 생성 설명에서 내용 없는 Markdown 제목이 통과하던 문제를 수정했다.
- 런북은 출처와 점검 항목 2개씩으로 줄이고, 설명을 확보하지 못하면 원인을 특정할 수 없다고 명시한다.
- 첫 사용자 질문·답변은 `results/chat_history_before_output_fix.md`로 보존했다. SQLite에는 질문·최종 답변·저장 시각이 남으며, 진행 이벤트와 전체 요청 시간은 저장하지 않는다.
- `sh/export_chat.py`로 이후 대화도 Markdown으로 내보낼 수 있다.
- 모니터링 값은 원본의 합성 데이터와 jitter로 생성된다. 실제 운영 서버 장애의 증거로 해석하지 않는다.

## 캡처 6장 검토 후 보완

- 내용 없는 단독 문장과 중복 문장을 제거하고, 이미 조회한 도구로 배포 이력 등을 확인하라는 생성 문장을 차단했다.
- 복수 서비스 검색에서 다른 서비스의 질문을 섞지 않고, 첫 알림에 한국어 절차 문맥을 붙여 대상별 대표 런북 1개를 찾는다. 알림이 없으면 선택을 보류한다.
- 일반 런북 절차는 진단 초안 작성·검수 없이 전체 절차를 표시한다.
- 이름 소개·회상은 같은 thread의 사용자 발화만 확인해 사용자의 이름을 에이전트 이름으로 말하지 않게 했다.
- 런북 원문의 도구 기능 설명을 수정했다. 조회할 수 없는 데이터는 별도 대시보드·로그·추적이 필요함을 명시했다.
- 수정 전 SQLite의 질문·답변 20개를 `results/chat_history_before_screenshot_fix.md`로 추가 보존했다.
- 자동 테스트의 실패 대상 집합이 `unittest.TestCase.fail`을 가리던 이름 충돌도 수정했다.
- 실제 검색 확인에서 복수 서비스의 짧은 영문 질의가 누락·오선택되는 사례를 발견해 첫 알림과 한국어 절차 문맥을 사용하는 방식으로 추가 보완했다. 최종 재확인에서 cache는 memory-leak, payments는 cpu-spike를 분리해 선택했다.
- 최종 로컬 기록의 단일 cache 지연 질문은 high-latency를 선택했다. 지연 질문에 대한 참고 절차이며 메모리 누수 확인을 의미하지 않는다. 모델 설명이 필터링되면 확인된 근거와 원인 판단 보류만 반환한다.
- 수정 후 실제 확인은 인프로세스 서버 핸들러로 수행했다. 브라우저의 수정 후 화면 캡처는 아직 새로 만들지 않았다.
